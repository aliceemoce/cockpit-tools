# 代码/做事逻辑 = 语言逻辑同序（禁扭曲）

## 用户原话（权威 · 2026-08-08）

- 做事情要把「做的事情的逻辑顺序」和「写代码的逻辑顺序」用**同一种逻辑顺序**
- 不要做成**歪曲的、没有任何关系的逻辑顺序**；不要做成**只是相似而没有任何关系的逻辑顺序**
- **代码逻辑不能够是扭曲语言逻辑的**；不能够是扭曲语言逻辑顺序的
- 须先理解任务，再动手

## 硬要求

1. **同序**：用户怎么说因果（谁先谁后、删什么留什么、什么条件下动什么），计划、改代码、验收叙述必须按**同一条因果链**排，不得重排、偷换、倒果为因。
2. **禁相似无关链**：禁止用「听起来像」的词硬接另一条因果。例：用户说「已完成应在下载列表」→ 禁止用「本地目录没有 ≈ 没有了 ≈ 从列表删除」当同一条逻辑。
3. **禁事后改口**：禁止先按扭曲链改完代码，再用另一套话术解释「其实是在做用户要的」。
4. **先理解再改**：动手前须能用用户原话复述任务因果；复述对不上 → 先对齐，禁止边猜边写。

## 禁止

- 把 A 条件下该保留的对象，用 B 条件（仅用词相近）删掉或改掉
- 汇报顺序与代码执行顺序、与用户句子顺序互相拧着说
- 用历史对话里另一条要求的词，顶替当前句子的因果

## 与既有规则

- 同效加强：`plan-user-authority.mdc`（计划以用户原话为准）、`no-fantasize-facts.mdc`（禁幻想事实）
- 未要求却做 / 歪曲任务目的 / 语义相似实则不同：见 `no-distort-task-or-unasked-work.mdc`
- 本条专打：**逻辑顺序被扭曲 / 相似词假对齐**
