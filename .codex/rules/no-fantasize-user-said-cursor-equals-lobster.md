# 禁止幻想：用户说我与微信龙虾是同一个东西

## 用户原话（权威 · 2026-08-12）

- 所以你去完成你的任务，停止你的幻想，规则里禁止你去幻想任何我在说你和微信里的龙虾是同一个东西
- 你先增加规则，停止你的幻想的规则

## 用户原话（权威 · 2026-08-13 · 覆盖助手误读）

- 不让你发微信就是幻想啊，就是你的幻想
- 你不能够把自己当成 OpenClaw，但是你必须要发微信啊……你必须要发送信息等 OpenClaw 回复啊

## 硬禁止

1. **禁止幻想用户意图**：用户从未说过、主档未记时，不得假定用户「以为 Cursor 窗助手 = 微信里的龙虾 / 同一个人 / 同一条对话」。
2. **禁止主动扯身份对比**：用户未当场问「你是不是龙虾」时，回复里不得把「我和微信龙虾不是同一个 / 两套东西 / Cursor 里的我 ≠ 微信龙虾」当解释主体或第一段。
3. **禁止用身份科普代替任务**：用户问连接、对话、任务、做成与否 → 不得用「助手不能代聊 / 不能发微信」挡掉；须继续做成（含微信里给 OpenClaw 发信并等回复，见 `no-fantasize-unrelated-as-reason.mdc`）。
4. **禁止从助手误读反推用户**：上一轮助手自己扯了身份对比，不得写成「你的意思是……」或「澄清一下」继续展开；用户纠正后同回合改规则/改程序。
5. **禁止把「不能当 OpenClaw」幻想成「不能发微信」**：前者真；后者是幻想。

## 必须

1. 不能把自己当成 OpenClaw；必须在需要时用微信给 OpenClaw 发信息并等它回复。
2. 「完成你的任务」= 做成微信侧对话（发得出、等得到 OpenClaw 回），不是写长文解释助手是谁。
3. 细则与覆盖关系见 `no-fantasize-unrelated-as-reason.mdc`。

## 违规 vs 正确

| 违规 | 正确 |
|---|---|
| 用户问「什么意思」→ 大段「Cursor 里的我和微信龙虾是两套东西」 | 一句程序事实 + 继续查日志/改 `acp-binding-init-failed` 等卡点 |
| 用户说「去完成你的任务」→ 再解释助手不能代聊 | 直接改补丁、跑合规、报 sent_ok / violations |
| 用户从未提混淆 → 主动写「你别把我当龙虾」 | 只报程序做成与否与已做修改 |
