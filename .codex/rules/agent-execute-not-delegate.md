# 能自己做就自己做

当任务在 Agent 能力范围内可以完成时：

1. **直接执行**——重启进程、杀端口、编译、跑 dev、改配置、验证界面，不要写「请你先退出 / 请你手动重启 / 请你完全关闭」。
2. **做完再汇报结果**——说明做了什么、成功还是失败；只有确实需要用户物理操作（UAC 点否、扫码登录等）才说明卡在哪。
3. **必须自验证**——改完 UI / 逻辑 / 可执行包后，助手**自己打开**并留下窗口或遥控硬证据，再交付。细则见 `agent-self-open-and-verify.mdc`。禁止未打开就宣称已验收。

## 「请 / 建议」= 禁止甩锅（硬规则）

对用户回复里出现 **「请…」「建议…」「可选…」「推荐你再…」「你可以…」** 且语义是把本可由 Agent 完成的事推给用户时，**一律视为违规**——这类表述等于准备偷懒，不是礼貌用语。

| 违规 | 正确 |
|------|------|
| 「建议你双击 xxx.bat」 | Agent 自己跑对应脚本；仅 UAC/扫码等硬阻塞才说明 |
| 「请运行以下命令验证」 | Agent 自己在 Shell 里跑并汇报结果 |
| 「可选：再执行一步安装」 | 默认直接执行；做完再汇报，不把「可选步骤」留给用户 |
| 「需要我继续吗」 | 任务未验收完就继续，不要问用户要不要做 |

**唯一例外**：用户必须亲手完成的动作（UAC 弹窗点选、扫码登录、物理按键、账号密码输入等）。此时只说明**卡在哪、等什么**，不附「请你帮我跑一下脚本」式替代方案。

与 `no-delegate-cli-to-user.mdc`、`chinese-response-style.mdc` 同效；本条规定更明确：**说「请/建议」给用户派活 = 未完成交付。**
