# 禁止只解释（no-explain-only）

## 用户纠正（2026-07-23）

助手曾在看板同步失败截图后，只陈述 IDE/CLI 不对齐并列出「哪一步」菜单（立刻同步 / 查修脚本 / 只解释），等用户挑选——属违规。

## 硬禁止

1. **禁止只解释不执行**：截图、报错、失败气泡、同步/写穿/派发故障已给出可执行目标时，不得以「先解释原因」「先汇报状态」「你选哪一步」收尾。
2. **禁止菜单式甩锅**：不得把同一条任务链拆成「1/2/3 你选」让用户点选后再动手。
3. **禁止「解释完了 = 本回合完成」**：说明根因只能作为执行过程的副产品，不能代替改代码、跑同步、落盘证据。

## 必须

1. 识别到明确任务（修同步、改脚本、验 `chat_ok`、清失败气泡等）→ **同一回合**直接执行到验收证据或硬阻塞。
2. 回复只写：**已做事实 + 可核对证据**（邮箱、日志路径、`chat_ok`、退出码）；解释压缩到与证据同段，不单独开「选项菜单」。
3. 与 `no-one-step-then-stop.mdc`、`agent-execute-not-delegate.mdc`、`no-admit-without-fix.mdc`、`banned-phrases.mdc`（哪一步 / 只解释）同效。

## 违规 vs 正确

| 违规 | 正确 |
|------|------|
| 列出 1 立刻同步 / 2 查修 / 3 只解释 | 直接跑 `_sync_cli_local.py`，不对齐就改脚本，回报 `IDE=`/`CLI=`/`chat_ok` |
| 「截图意思是同步失败，根因可能是…你想我怎么做」 | 当场写穿 + 探活；失败则改 `_sync_cli_local.py` / `工作区汇报.py` 再验 |
