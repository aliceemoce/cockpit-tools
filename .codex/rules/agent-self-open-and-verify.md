# 助手自己打开、自己验证（硬）

## 用户原话（权威）

- 你自己打开，你自己验证，全局规则如果没有这么要求就加上

## 用户纠正（权威 · 2026-08-09）

- 计划须自带「去实践测试」的硬要求；不得写成可有可无的收尾
- 规则须适用于所有工作情况，不得写成某一仓/某一程序专用话术才算验收
- **全职规则须要求截图；须要求助手去看截图**；步骤要留痕；禁止只报接口 JSON 冒充已看见界面

## 硬要求

1. 交付涉及界面、可执行包、本机应用、或用户可感知的结果时：**助手本人**打开或拉起目标（桌面窗按本机 GUI 代启规则），并用控件探测/约定遥控/接口留下可核对证据。
2. **禁止**写「请你打开看一下」「你本地验证」「以你目视为准」代替助手验收。
3. 未自己打开/运行 + 未留下硬证据 → **不得**宣称已验收、已完成。
4. 与 `agent-execute-not-delegate.mdc` 同效：自验证是必须，不是尽量（硬阻塞除外：UAC、扫码、用户物理键）。
5. **写计划时**：实质性任务的计划必须含「实践测试（硬门禁）」节，细则见 `detailed-plans.mdc`；缺节或只有现象口号 = 计划不合格，不得开改。

## 有界面：截图 + 看图（硬 · 2026-08-09）

凡验收对象是**可见界面**（桌面窗、网页、安装器、播放器等），实践测试还必须：

1. **截图留痕**：把目标窗（或关键区域）截成图片文件，路径写入本回合可核对位置（工作区证据目录或工具返回的图片）。
2. **亲自看图**：用读图能力打开该截图，根据**图上实际可见内容**写结论（看见了什么控件/文案/状态）。
3. **禁止**：只引用遥控/API/`ok:true`/进程句柄，却从未截图、从未看图，就写「已在某某页」「已切到某某」。
4. **图文须一致**：口头说的页面/状态必须能在刚看过的截图里指认；对不上 = 验收失败，继续查，不得改口硬圆。

## 验收最低证据（通用）

按交付形态至少满足，并在计划里预先写死：

- **有窗**：交互会话一致、窗口标题非空、主窗口句柄非 0（适用时）+ **截图文件 + 看图结论** + 对目标操作的客观结果
- **无窗**：主路径命令/接口的退出码与关键输出原文，或约定成功结构及关键字段
- 需要时另加：控件树、日志关键字原文

## 禁止

- 只编译通过、只改代码、只覆盖产物文件，就当验收完成
- 把打开与核对推给用户
- 用「验收清单写了应有现象」代替本人已执行的实践测试
- **只甩 JSON/日志、不截图、不看图**，却宣称已看见界面状态
