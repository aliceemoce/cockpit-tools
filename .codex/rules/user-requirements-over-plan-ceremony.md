# 按用户要求做，禁止计划仪式交差

## 硬原则

1. **完成标准 = 用户要求 / 历史要求主档**，不是 plan 勾选表、merge parents、SHA、截图清单或 PR/Release 是否存在。
2. **Plan / Agent 内部待办**只是执行手段；勾完计划 ≠ 完成用户目标。
3. 用户要求含 **fork 行为仍在可运行产品里**（函数有调用点、事件有监听、切号/跟号链路活着）时：仅证明「源码血统 / 页 blob / 安装成功」算 **未完成**。

## 禁止

- 计划写「怎么交差」，却把用户要的行为验收踢出完成条件。
- 用 merge parents、Cursor 页行数、无整棵换 `src/`、exe SHA、一张 UI 截图、PR URL **单独或组合**宣称「已修好 / 已完成 / 能用」。
- 已知主档/设计档记录 fork 能力缺失，仍按计划把同步/合并标完成。
- 计划与主档冲突时沿计划走；冲突须以用户当场要求与主档为准（见 `user-history-requirements.mdc`）。
- 对用户说「计划完成标准已满足」而用户关心的能力未验收或已证伪。

## 必须

| 场景 | Agent 行为 |
|---|---|
| 开 Plan / 写验收 | 每条完成条件映射到**用户原话或 HR 条目**的产品行为 |
| 合并 upstream | 对照允许的 fork tip：**独有调用链、emit/listen、切号行为**是否仍在；仅 blob/parents 不够 |
| 宣称已修好 | 用户当次要求的**全部行为**有磁盘/源码调用点/UIA（按任务）证据 |
| 发现计划窄于用户要求 | **改计划或扩验收**，不得缩用户目标去迁就计划 |

## 本轮教训锚点（2026-07-15）

- 用户：真合并 = 真用 fork + 线上，**功能还在**。
- 违规：计划只验 parents/页 blob/SHA/截图 → 标已修好，而 `sync_cursor_local_watch` + `accounts:changed` listen 已丢。
- 正例：合并关闭条件含「fork 该有的后台/前端链路调用点仍存在且可运行」。
