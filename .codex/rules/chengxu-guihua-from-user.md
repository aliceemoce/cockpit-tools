# 程序规划（全局硬约束）

## 名称

「程序规划」= 工作区程序规划 / 工作区规划。须落盘为每轮强制进上下文的工作区规则，并与三件套同稿。

语音误识：勿把「程序规划」写成「城市规划」；历史误写一律改回「程序规划」。对应栏目写「程序要求」，勿写「城市要求」。

## 必须同时具备两块（硬要求）

程序规划**不合格**若缺任一：

1. **用户自然语言来源** — 须能指出用户说过的目标与边界从哪来（主档 / 原话摘录）；并写进规划里可核对的「用户原话来源」或等价节。用户原话未进规划 = 未做程序规划。
2. **程序要求（程序定义）** — 按程序要求与助手要求分界：**工作区目标、设计目的、程序定义与子系统、全量功能、数据与持久化、对外接口**。写的是「这台程序是什么、有哪些能力」。
3. **具体代码实现** — 「代码实现」须落成**多个文件**（禁止只用一份过短单文件交差）；每项能力对照到真实模块/脚本/补丁/配置落点。目录建议：工作区「程序规划」分册目录（目的、程序要求、各业务代码实现、如何检查、原话来源等）。

### 禁止当成「程序要求」的东西

- 某次修漏洞的黑话、内部绰号、验收碎片（例如把一次故障说法当成产品栏目）。
- 助手动作清单、巡检勾选、过程管理冒充程序规格。
- 只有白话口号、没有子系统与功能清单；或只有文件清单、没有程序定义与用户原话来源。

助手只可补充步骤与落点，不得用自拟禁令清单、巡检勾选顶替用户原话，也不得用「规则里写了再去读别的文件」代替把实现落点写进本规划。

## 正文用字（2026-07-28 用户口径 · 覆盖旧「代码实现栏允许拉丁字母」）

程序规划、工作区程序规划注入规则、三件套正文，用字只认下列允许项；旧规则「代码实现栏允许路径/文件名中的必要拉丁字母当叙述」作废。

### 允许

1. **中文**叙述能力、流程、验收口径
2. **真数字**：时刻（如 03:00）、数量、时长等文字数字
3. **贴吧名称**一类无英文语义的专名（字母串本身不是英文单词用法）
4. **非英文**字母（如日文假名等，若业务需要）
5. **非函数的字母串**：仅作磁盘落点标识（目录/文件名），用可点击引用给出路径；不得当英文单词、缩写或函数名来讲道理

### 禁止

1. **任何英文单词**（含套话、禁令口号、产品黑话当正文）
2. **任何英文缩写**（不得用缩写顶替中文能力名）
3. **任何函数名**（不得把函数标识符写进规划当正文）
4. **代码占位符伪装成数字/标识**：看起来像数字或字段、实为脚本占位/通配/步骤代号（如假字段名、带星号的字段模板、工程步骤英文代号）——一律禁止
5. 用一份过短的「代码实现」单文件冒充完整程序规划

### 落点怎么写

- 能力用中文写清；落点用「可点击文件引用」对准磁盘文件
- 禁止在正文里展开函数调用链、缩写术语表、英文参数名堆砌

## 结构（目的驱动，非禁令驱动）

顺序固定；**代码实现必须多文件分册**，不得挤进一份过短单文件：

1. **目的** — 这台程序要成就什么
2. **程序要求** — 程序定义（目标、子系统、全量功能、数据、接口）；另附「用户原话来源」
3. **要做成的能力** — 可与程序要求同稿摘要
4. **代码实现（多文件）** — 按业务分册：能力对照具体文件/模块
5. **如何检查** — 对照目的与规格，找出不符合处并改程序
6. **账号与接口** — 若用户要求过：桌面登录写穿、用量字样是写穿做错的症状不是终点、须持续重试直到可对话
7. **短附录** — 边界可极短；禁止用「不能做什么」堆成主体
8. **用户原话来源** — 用户自然语言摘要（可放文末）

## 自动化

本地自动化的提示词须**从该工作区现行程序规划导出**：先写目的与程序要求，再写「对照目的与代码实现检查哪里不符并改到符合」。禁止自动化提示词变成禁令清单或与程序规划无关的空提示。

硬纠正：本地自动化派发的必须是对话任务。禁止把自动化做成单纯的脚本测量/审计报表层交差。对话中用工具可以，外包成测量脚本交差不行。

## 与已有全局规则

同效加强：计划以用户原话为准、禁止跳过程序计划、程序计划工作优先、工作区三件套与程序规划落盘。本条专打：缺程序要求、缺代码实现对照、规划里堆英文单词/缩写/函数、用量当终点、把程序规划误写成城市规划、代码实现只写一份过短文件。
