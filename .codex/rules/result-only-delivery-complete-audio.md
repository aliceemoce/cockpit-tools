# 只认结果：完整音频 + 打开播放证据

## 用户模式（硬约束）

- 用户**不再给建议**，只**看结果**：**是白 = 批准**；**不是白 = 重做**。
- 用户**不再教**助手任何事。已写入主档/规则的标准不得再问、不得让用户定义。
- 验收标准不变：**白的声音 = 非垃圾；其他角色声音 = 垃圾**。

## 交付物（必须）

| 算交付 | 不算交付 |
|--------|----------|
| **完整音频文件**（可播放的 `.wav` 等，一条或一组明确路径） | 仅 `manifest` / `csv` / `json` / `pass_rate` / 日志 |
| 音频内容为**白的讲话**（无其他角色声线） | 毫秒碎屑（无完整语句意图的极短切片当最终交付） |
| 助手已**亲自打开**并留下**正在播放的证据** | 只打开资源管理器、CSV、网页、播放列表而不播 |

**「完整音频」**：至少一条可独立播放、能听清是谁在说话的导出片段；不得以「跑完脚本」代替。

## 打开与播放证据（必须，交付前完成）

1. 用 Shell `Start-Process` 打开**具体音频文件路径**（系统默认播放器或已安装的 VLC 等）；**禁止** Edge/HTML/内嵌浏览器当试听交付。
2. 用 **UIA MCP**（`ui_find_window` → 播放器进程/标题）证实播放器窗口存在。
3. 读取播放状态或等价证据（播放中 / 时长在走 / 控件 Name 含 Playing 等）；必要时 `ui_screenshot` 留证。
4. 回复中写明：**路径、播放器窗口、播放证据**（可核对事实，不写「应该已打开」）。

**未满足播放证据 = 未交付**，不得写「已完成」「已验收」。

## 重做与换法

- 用户判非白 → **重做**，不是改文案。
- 同一链路已失败（见工作区 `failure-lessons-shiro-extract.mdc`）→ **换方法**，禁止第 N 次只调阈值再跑同一管道。
- 想避免永远重做：**先过关再扩 scope**（例如 E01 一条完整白音频过关再批下一集）。

## 禁止

- 把 manifest 行数、复检 pass_rate、编译通过当作交付完成。
- 未经打开+播放证据宣称「可试听」「已打开」。
- 用户拒收后仍用新说法推同一套无效链路。
