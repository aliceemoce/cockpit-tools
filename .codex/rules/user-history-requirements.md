## 主档

- 持久化文件：**当前工作区根** `.cursor/user-history-requirements.md`
- **用户原话（权威）**：由脚本自动提取每条用户消息全文，写入「用户原话自动同步」节；索引在 `.cursor/user-history-sync.json`
- **禁止**：助手手工「摘要/摘抄/改写」用户原话冒充主档；助手只允许写**程序归纳**（非用户原话）或运行同步脚本
- 用户当场明确推翻旧说法时：在主档手工节标注旧条目被哪条新消息取代，**不得静默忽略**

## 同步脚本（硬路径 · 自动化为主）

- 权威脚本：`%USERPROFILE%\.cursor\scripts\sync_user_utterances.py`（**必须** `--workspace <当前工作区根>`；中文名入口仅兼容转调）
- **自动化（主路径）**：`~/.cursor/hooks/sync-user-history.ps1`，挂在 `workspaceOpen` / `sessionStart` / `beforeSubmitPrompt` / `stop`
  - 从 hook **stdin JSON** 的 `workspace_roots` 取当前工作区（与 `sync-global-rules` 同法）；不得只靠常为空的环境变量然后静默跳过
  - 日志：`~/.cursor/hooks/sync-user-history.log`（须能看到 `ok workspace=...`）
- **禁止**：调用其他工作区路径下的同步脚本；禁止写死看板仓路径当默认
- **禁止**：把 Desktop 父根全机 `agent-transcripts` 灌进子工作区主档
- 助手仅在 hook 未跑通（日志无 ok / 本仓 `last_sync_at` 明显过旧）时补跑同一全局脚本；日常不得用手工同步代替自动化

## 续做与「上一条对话」

- **上一条对话** = **本仓**主档「续做死会话链」表**最后一行**的 composerId 对应本仓映射的 `agent-transcripts/<id>/<id>.jsonl`（按 mtime）
- **不是**其他工作区主档、**不是**看板 `chats/*.jsonl`、**不是**本 Session 聊天里第 N 条消息、**不是**主档旧「未完成」条
- 用户说「继续 / 上一条死了」→ **先**读上一条 transcript 末 30 行 → **再**读**本仓**主档
- 死会话链由同步脚本**整表重写**；助手不得手工改表体冒充已登记

## Agent 硬约束

1. **不可违背**：规划与执行任何任务前，先对照**本仓**主档（含自动同步节）
2. **冲突即停**：两条及以上历史要求矛盾时，停止并用 `AskQuestion` 请用户裁决
3. **当场纠正优先**：用户最新消息若明确纠正旧要求，以该消息为准；运行同步脚本落盘，禁止只口头认

## 优先级

用户当场纠正 > 用户对历史冲突的裁决 > **本仓主档（含自动同步用户原话）** > 项目内其它规则与文档

改代码或跑 shell 前须阅读**当前工作区** `.cursor/user-history-requirements.md`（若存在），并用全局脚本 + `--workspace` 更新本仓主档。
