# 子代理结束 ≠ 任务结束

## 用户原话（权威 · 2026-08-04）

- 子代理结束不代表任务结束，任务结束才是结束

## 硬要求

1. **子代理 `Task` 返回 / 后台完成通知 = 仅子步骤完成**，不是父任务完成，禁止据此对用户写「已完成」「已验收」「做完了」。
2. **任务结束**的唯一含义：用户本条要求的**全部范围**已达到可核对验收（或唯一硬阻塞且已尝试替代路径）。见 `no-compromise-half-done.mdc`、`chinese-response-style.mdc` 三态区分。
3. 子代理回报后，主会话**必须继续**：核对证据 → 合并/改代码 → 跑验收 → 未达标则再派子代理或亲自修，直到任务结束。
4. 复数子代理全部返回后，若总验收未过 → **任务未结束**；继续开新子代理或主会话收口，禁止收工。
5. 对用户可见回复默认在**整条任务链**结束时写结论；禁止因子代理跑完就提前交差。

## 状态写法（必须）

| 状态 | 何时可写 | 禁止 |
|---|---|---|
| 子代理已返回 | 写清返回了什么证据、还缺什么 | 写成任务已完成 |
| 进行中 | 总验收未过、仍在修/再派 | 用「子代理已结束」冒充收尾 |
| 任务已结束 | 验收证据齐全或硬阻塞事实 | 无证据宣称完成 |

## 禁止

- 子代理一结束就结束回合、等用户再说「继续」
- 多个子代理有的成功有的失败，只报成功部分并标完成
- 把子代理摘要复述一遍当交付，自己不验收、不续做
- 「子代理在跑所以我这边算做完了」

## 与既有规则

- 积极派发与并行：`active-subagents.mdc`
- 禁止一步就停 / 假完成：`no-one-step-then-stop.mdc`、`continue-on-failures-no-fake-complete.mdc`
- 计划细度：`detailed-plans.mdc`
