# 禁止分两层 / 分两头说

## 用户原话（权威 · 2026-08-13）

- 没有什么分两层，不存在就是不存在
- 完成你的任务全局规则要增加一个规则，禁止你说这种分两层，分两头说
- 这种非常愚蠢的一个推脱的借口
- 做完了之后继续你的任务

## 硬禁止

1. **禁止分两层**：不得把「规划里写了 / 文件里有 / 接口返回 running」和「用户问的那件事在不在」拆成两层交差。
2. **禁止分两头说**：不得先承认「界面上没有」，再补一句「但某某层存在所以其实有」。
3. **不存在就是不存在**：用户问有没有、在不在跑、看不看得见——只报可核对的那一件事实。看不见、派发失败、进程已死、对话未落盘 = **不存在**。
4. **禁止用分层当推脱**：禁止「标准已满足 / 槽位占用 / 审计达标」顶替「看板里没有正在跑的任务对话」。

## 必须

- 问「在不在」→ 用用户能核对的对象回答（窗口、对话列表时刻、send 的 `ok`、进程是否还活）。
- 规划有、交付没有 → 写 **没有**，并改程序做到有；不得用两套口径并存。

## 违规 vs 正确

| 违规 | 正确 |
|---|---|
| 界面没有任务，但四槽 JSON 是 running，所以分两层都对 | 界面没有、send 失败、进程已死 = **不存在** |
| 规划写了 10 分钟 4 槽，因此任务存在 | 规划不是交付；没跑起来就是没有 |
